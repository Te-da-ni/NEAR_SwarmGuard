# NEAR SwarmGuard

NEAR SwarmGuard is a Python 3.11 and Streamlit demonstration of three agents passing typed messages in sequence. Scout gathers public NEAR network status and token price metrics. Analyst turns those metrics into a non-binding risk assessment and proposal. Executor applies a human-written spending policy in Python, records the decision, and can request a dry quote when the proposal passes policy.

The problem addressed is how to inspect an agent's recommendation against explicit spending limits before a transaction flow is considered. The app makes the proposal, policy result, deciding rule, dry quote, and audit trail visible. It does not connect to a wallet, sign an intent, submit an intent, or broadcast a transaction. It uses no database; the sample snapshots and audit log are local JSON files.

## How NEAR is used

- **NEAR AI Cloud** runs Analyst inference through its OpenAI-compatible API. The request contains Scout's public metrics and asks for a schema-checked JSON recommendation. NEAR AI Cloud describes its API as secure, private inference routed to models in Trusted Execution Environments. See the [NEAR AI Cloud quickstart](https://docs.near.ai/cloud/quickstart).
- **NEAR** supplies network status through the public RPC endpoint configured in `agents/scout.py`. Scout uses CoinPaprika's public ticker endpoint for token prices. See [NEAR RPC providers](https://docs.near.org/api/rpc/providers).
- **NEAR Intents** supplies the supported-token catalogue and a `/v0/quote` request with `dry: true` after Executor approves a swap proposal. The documented unsigned-intent flow informs the boundary shown in the dashboard, but the app does not call the intent-generation endpoint. See [Request a swap quote](https://docs.near-intents.org/api-reference/oneclick/request-a-swap-quote) and [Generate an intent for signing](https://docs.near-intents.org/api-reference/oneclick/generate-an-intent-for-signing).

### Dry quote limitation

The NEAR Intents dry quote does not return a `depositAddress`. The official [`generate-intent` endpoint](https://docs.near-intents.org/api-reference/oneclick/generate-an-intent-for-signing) requires that address. SwarmGuard therefore does not call `generate-intent` and does not invent or fill in a deposit address. If a dry quote succeeds, the dashboard shows a local preview assembled from the policy decision and quote, labeled **“Draft intent (not generated by generate-intent, not signed, not submitted)”**. It is not an official NEAR Intents intent payload. The dashboard shows the requested asset pair as the route because the documented dry quote response does not provide a solver route; it distinguishes the requested deadline from any deadline returned by the quote.

## Run locally in demo mode

Demo mode uses `data/sample.json` and `data/analyst_sample.json`, and makes no API requests. With `NEAR_AI_API_KEY` unset, the dashboard selects demo mode by default.

1. **Do:** Create and activate a Python 3.11 environment from the project folder in PowerShell:

   ```powershell
   py -3.11 -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   **See:** PowerShell uses the project's `.venv` environment.

2. **Do:** Install the project libraries:

   ```powershell
   python -m pip install -r requirements.txt
   ```

   **See:** The Streamlit, HTTP, charting, and OpenAI client dependencies install into `.venv`.

3. **Do:** Start the dashboard:

   ```powershell
   streamlit run app.py
   ```

   **See:** A browser opens to the SwarmGuard dashboard. Demo mode is selected by default when `NEAR_AI_API_KEY` is unset.

4. **Do:** Select Demo mode and click Run swarm. **See:** The saved Scout metrics in the chart, the saved Analyst `hold` proposal, and the Executor policy decision in the coordination log. Since the fixture proposes no swap, Executor does not request a quote. It appends an audit record.

5. **Do:** Click Verify audit log. **See:** Whether the local hash chain verifies and how many records were checked.

On macOS or Linux, activate the environment with `source .venv/bin/activate` after creating it with `python3.11 -m venv .venv`.

## Run with live services

Live mode fetches public Scout data and calls NEAR AI Cloud for Analyst inference. An approved swap proposal can cause Executor to request a NEAR Intents dry quote. The dashboard allows at most five runs per Streamlit session and enforces a 60-second minimum between runs.

1. **Set the needed values in the PowerShell process that will run Streamlit**. Keep the AI key out of source files and version control:

   ```powershell
   $env:NEAR_AI_API_KEY = "YOUR_NEAR_AI_CLOUD_KEY"
   $env:NEAR_INTENTS_ACCOUNT_ID = "YOUR_PUBLIC_ACCOUNT_ID"
   # Optional partner key:
   $env:NEAR_INTENTS_API_KEY = "YOUR_NEAR_INTENTS_PARTNER_KEY"
   ```

   `NEAR_AI_API_KEY` is needed for live Analyst inference. `NEAR_INTENTS_ACCOUNT_ID` is needed only if an approved swap reaches the quote step. The partner key is optional. The app also reads Streamlit secrets. `.env.example` documents the variable names but is not loaded automatically.

2. **Run Streamlit from the same terminal**:

   ```powershell
   streamlit run app.py
   ```

3. **Turn off Demo mode and click Run swarm**. See whether Scout data is fresh or marked stale, the Analyst proposal, and the Executor's explicit policy decision. Network and rate-limit failures appear in the coordination log. If policy approves a swap and an account ID is present, the Executor requests only a dry quote and displays its returned fields and the local preview draft.

4. **Verify the audit log in the dashboard**, or from another terminal in the project folder run:

   ```powershell
   python -m agents.executor --verify
   ```

## Spending policy and audit log

`policy.json` is the human-authored policy. It contains `allowed_tokens`, `max_amount_usd`, `min_confidence`, and `cooldown_seconds`. The Executor checks the proposal and resolved NEAR Intents asset IDs in ordinary Python before requesting a quote. The included policy allows `nep141:wrap.near` and `nep141:usdt.tether-token.near`, caps a proposal at USD 5, requires confidence of at least 0.7, and sets a 60-second cooldown.

Each Executor decision is appended to `logs/audit.jsonl`. Every record stores the previous record's SHA-256 hash and its own hash; the dashboard verifier recomputes the chain. The file is created at runtime and is ignored by Git.
